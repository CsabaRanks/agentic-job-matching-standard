# Contributing

Thank you for your interest in AJMS. This is an early Community Draft. Feedback on the model is as valuable as code.

## Ways to contribute

- **Open an issue** for a criterion that is missing, ambiguous or wrongly modelled. Please describe the real-world case (no personal data).
- **Propose a domain criterion**: name the owner namespace (reverse DNS), the data type, the unit (UN/CEFACT code) and the comparator, and show one candidate-side and one job-side example.
- **Report a mapping error** against schema.org or another format, with a link to the official source.
- **Implement AJMS** in another language. Independent implementations are the best test of the specification.

## Ground rules

1. **No personal data.** Examples must be synthetic. Use `example.org`, `example.com` or `example.net` for addresses. Do not commit CVs, screenshots, PDFs or exports of real profiles. The test suite rejects e-mail addresses outside example domains, phone numbers and secret-like tokens.
2. **No unverifiable claims.** Do not claim support by schema.org, search engines, ATS vendors or compliance with laws. Cite official sources with a retrieval date in `docs/sources.md`.
3. **No invented security.** Do not add placeholder cryptography. Security-related extensions must build on reviewed, published specifications.
4. **Unknown stays unknown.** Code must never turn a missing value into 0, "no" or a failed requirement.

## Development

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[test]"
ajms check        # examples, negative cases, JSON-LD, generated outputs
pytest            # full test suite
```

- After changing schemas, examples or rendering, run `ajms build-examples` and commit the regenerated files. `ajms check` fails when a generated file is out of date.
- Negative examples are generated by `python tools/make_invalid_examples.py`. Each one is a valid example with exactly one mutation and an expected error (kind, JSON pointer, message fragment) in `examples/invalid/expectations.json`.
- Every new property in a profile schema needs a term in the JSON-LD context. A test enforces this.
- New import adapters: see [docs/import-adapters.md](docs/import-adapters.md#writing-a-new-adapter). Fixtures must be synthetic or fully sanitised.

## Changing the standard

- Published schema files under `schemas/v0.1/` are not changed after the `v0.1.0` release (they are served as schema IDs via GitHub Pages). Breaking changes go into a new schema line (`schemas/v0.2/`) with a new version and tag.
- Describe the change in `CHANGELOG.md` and, if it affects the model, in `docs/specification.md` and `docs/field-catalog.md`.

## Security

AJMS contains no security mechanism. If you find a way in which the reference tools could leak data (for example a view derivation that keeps identifying fields), please open an issue without including real personal data.
